The spec says what the product does as its users see it, never how it is built. This product is a CLI and a set of agent prompts, so its surface is technical: commands, flags, printed output, exit codes, lint codes, the files a user writes or the tool writes (`spec/`, `spec/config.json`, ticket files, generated skills and agents), and the role prompts' observable rules all belong in the spec. Its internals do not: no source module, class, function or dependency names, and no `Code:` lines.
