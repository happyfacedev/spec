# graph contracts

### graph.Build
Kind: operation · Status: active
`spec build`: writes `index.md` and `_generated/graph.json` under the spec root, each only when its content changed. Exits 0 when it built, 1 when the spec does not parse.
Output: graph.BuildSummary | graph.SpecDoesNotParse

### graph.BuildSummary
Kind: type · Status: active
What `spec build --format json` prints after a build. In text, the same facts are the line `<spec>: <nodes> nodes, <edges> edges, <scenarios> scenarios`, then one `wrote <path>` line per file written, or `up to date` when none was.

#### graph.BuildSummary.spec
The spec version: `spec@` and the first 8 hex digits of a SHA-256 over the authored spec files. Type: string

#### graph.BuildSummary.written
The generated files this build wrote, relative to the spec root, `_generated/graph.json` before `index.md`; empty when both were already current. Type: string[]

#### graph.BuildSummary.nodes
How many entries `nodes` in `graph.json` holds. Type: int

#### graph.BuildSummary.edges
How many entries `edges` in `graph.json` holds. Type: int

#### graph.BuildSummary.scenarios
How many entries `scenarios` in `graph.json` holds. Type: int

### graph.SpecDoesNotParse
Kind: error · Status: active
`spec build` found a file it cannot parse, so it writes nothing and exits 1. In text it prints `build stopped: the spec does not parse` and the parse errors as lint prints findings, on stderr. With `--format json` it prints the spec version, an empty `written` and the errors as `findings`, on stdout.

#### graph.SpecDoesNotParse.findings
The parse errors only: lint findings that are not parse errors do not stop a build. Type: lint.Finding[]

### graph.Index
Kind: entity · Status: active
`index.md` at the spec root: the modules by domain, one line per feature. Generated, committed, never edited by hand. It holds no spec version and no line numbers.

#### graph.Index.title
The first line: `# <name>-spec index`, with the `name` from `config.json`, or `# Spec index` when there is none. Then a blank line and `` Generated by `spec build`. Do not edit; run `spec show <ID>` for any line. ``. Type: string

#### graph.Index.domains
One section per module domain, ordered by domain name. Type: graph.IndexDomain[]

### graph.IndexDomain
Kind: type · Status: active
One `## <domain>` section of `index.md`.

#### graph.IndexDomain.name
The domain, as the modules' `domain` names it. Type: string

#### graph.IndexDomain.modules
The domain's modules, in natural ID order. Type: graph.IndexModule[]

### graph.IndexModule
Kind: type · Status: active
One module's entry in `index.md`.

#### graph.IndexModule.heading
`### <module> · <prefix>`, followed by ` (<status>)` when the module is not active. Type: string

#### graph.IndexModule.summary
The first sentence of the module's description, on the line under the heading; left out when the description is empty. Type: string?

#### graph.IndexModule.features
One line per feature of the module, in file name order: `- <ID> <title>`, followed by ` (<status>)` or ` (<status> → <superseded_by>)` when the feature is not active. Type: string[]

### graph.Graph
Kind: entity · Status: active
`_generated/graph.json` under the spec root: every unit and link, for people and other tools. Written by `spec build`, ignored by git, and read back by no command. Two builds of the same files are byte-identical: keys in a fixed order, two-space indent, LF line ends, a trailing newline.

#### graph.Graph.spec
The spec version, `spec@` and 8 hex digits. Type: string

#### graph.Graph.nodes
Every unit but scenarios, in natural ID order. Type: graph.Node[]

#### graph.Graph.edges
Every link once, plus the derived module dependencies, sorted by from, then to, then kind. A scenario's cites are not edges: they are in `scenarios`. Type: graph.Edge[]

#### graph.Graph.scenarios
Every scenario of every feature, in natural ID order. Type: graph.GraphScenario[]

#### graph.Graph.questions
Every question on a module, feature, decision or screen, sorted by owner, then ID. Type: graph.GraphQuestion[]

#### graph.Graph.terms
Every glossary term, in glossary order. Type: graph.GraphTerm[]

### graph.NodeType
Kind: type · Status: active
The unit types `graph.json` lists as nodes. Type: "module" | "feature" | "rule" | "contract" | "field" | "invariant" | "decision" | "screen"

### graph.Node
Kind: type · Status: active
One unit in `graph.json`.

#### graph.Node.id
Type: string

#### graph.Node.type
Type: graph.NodeType

#### graph.Node.kind
Contracts only: entity, event, operation, type or error. Type: string?

#### graph.Node.module
Features, rules, contracts and fields: the module the unit belongs to. Type: string?

#### graph.Node.title
A feature's, invariant's, decision's or screen's title, a rule's text, or a contract's one-line summary. Modules and fields have none. Type: string?

#### graph.Node.status
A rule takes its feature's status. Type: format.Status

#### graph.Node.file
The file that defines the unit, relative to the spec root. Type: string

#### graph.Node.line
The line it starts on. Type: int

### graph.EdgeKind
Kind: type · Status: active
What an edge says. A feature's links keep their frontmatter names; `uses` is a contract typed by another; `shows` and `calls` also come from screens; `applies` from an invariant's `Applies to:`; `cites` from a rule or a question; `depends_on` is a derived module dependency. Type: "reads" | "writes" | "emits" | "consumes" | "provides" | "calls" | "observes" | "invariants" | "decisions" | "ui" | "uses" | "shows" | "applies" | "supersedes" | "superseded_by" | "cites" | "depends_on"

#### graph.Edge.kind

### graph.Show
Kind: operation · Status: active
`spec show <ID>`: one unit as its file stores it, plus the units that link to it. Exits 0, or 2 when it refuses.
Output: graph.ShownUnit | graph.UnknownId | cli.UsageError

#### graph.Show.id
A unit ID, a glossary term or alias in any case, or a ticket ID. Type: string

### graph.ShownType
Kind: type · Status: active
What `spec show` found. Type: "module" | "feature" | "scenario" | "rule" | "contract" | "field" | "invariant" | "decision" | "screen" | "term" | "ticket"

### graph.ShownUnit
Kind: type · Status: active
What `spec show --format json` prints. In text: `<file>:<line>`, a blank line, the stored text, and when it has backlinks a blank line, `## Backlinks (generated)`, then `Used by:` with one `- <id> <kind> — <title>` line each and `Cited by:` with one `- <id> — <title>` line each; ` — <title>` is left out when the title is empty.

#### graph.ShownUnit.spec
The spec version. Type: string

#### graph.ShownUnit.id
The ID as given; for a term, the term's own name. Type: string

#### graph.ShownUnit.type
Type: graph.ShownType

#### graph.ShownUnit.file
Relative to the spec root; a ticket's is relative to the project. Type: string

#### graph.ShownUnit.line
1 for a ticket. Type: int

#### graph.ShownUnit.status
The unit's status; a scenario or rule takes its feature's, a ticket its ticket status, and a term has none. Type: string | null

#### graph.ShownUnit.text
The unit's text as stored: a file's whole text, a heading's section, a scenario's heading and steps, or a rule's `- R<n>: <text>` line. Type: string

#### graph.ShownUnit.usedBy
Every link to the unit that is not a cite or a `superseded_by`, sorted by ID, then kind. Type: graph.Backlink[]

#### graph.ShownUnit.citedBy
Every scenario, rule or question that cites the unit, once each, sorted by ID. Type: graph.Citation[]

### graph.Find
Kind: operation · Status: active
`spec find <words>`: searches unit IDs, titles and glossary terms, best first. Exits 0, also when nothing matches, or 2 with no words.
Output: graph.FindResult | cli.UsageError

#### graph.Find.words
The words to search for, matched without regard to case. Type: string[]

### graph.FindResult
Kind: type · Status: active
What `spec find --format json` prints. In text, one `<id>  <type>  <title>` line per hit, two spaces apart, or `no matches for "<words>"` when there is none.

#### graph.FindResult.spec
The spec version. Type: string

#### graph.FindResult.query
The words, joined by single spaces. Type: string

#### graph.FindResult.hits
At most 20, highest score first, ties in natural ID order. Type: graph.FindHit[]

### graph.FindHit
Kind: type · Status: active
One unit or term that matched.

#### graph.FindHit.id
A unit ID, or a term's name. Type: string

#### graph.FindHit.type
A unit type, `scenario` included, or `term`. Type: string

#### graph.FindHit.title
What the hit's title words were matched against: a unit's title, a rule's text, a contract's summary, a member's description line, a module's first sentence, or a term's definition. Type: string

#### graph.FindHit.score
The sum, over the words, of 100 for an ID equal to the word or 30 for an ID holding it, 50 for a term or alias equal to it, and 10 for the word, or its plural in s or es, as a whole word in the title, or 4 for the word anywhere else in it, plus, for a query of two or more words, 100 for an ID equal to the words joined by single spaces and 50 for a term or alias equal to them. Type: int

### graph.ComputeImpact
Kind: operation · Status: active
`spec impact <ID|TICKET> [--depth n]`: the reach of a change, from the spec files alone. Exits 0, or 2 when it refuses.
Output: graph.Impact | graph.UnknownId | graph.NotAnImpactTarget | cli.UsageError

#### graph.ComputeImpact.target
A feature, scenario, rule, contract, member, invariant, decision or screen ID, or a ticket ID. Type: string

#### graph.ComputeImpact.depth
`--depth n`: how many steps the re-verify ring follows consumers' outputs; 1 when left out. Type: int?

### graph.Impact
Kind: type · Status: active
The reach of a change to one unit or one ticket: what `spec impact --format json` prints. In text: `# Impact · <target> · <spec>`; a `Changed: <IDs>` line (`Reworked:` for a task) when any feature changes; for a task, `A task changes no behaviour: everything below must hold exactly as it is.`; then `## Must change (<n>)` (`## Must hold (<n>)` for a task), `## Re-verify (<n>)` and `## Scope gaps (<n>)`, each with its items or `None`; then `Unresolved: <IDs>` when any.

#### graph.Impact.target
The ID impact was asked for. Type: string

#### graph.Impact.spec
The spec version. Type: string

#### graph.Impact.holds
True for a task: it changes no behaviour, so the inner ring is what must keep holding. Type: bool

#### graph.Impact.changed
The features the change itself edits, in natural ID order. Type: string[]

#### graph.Impact.mustChange
The inner ring: units the change edits, besides the changed features. In text, each is `- <id> <title>`, then `  via: <via, joined by "; ">` and, when any, `  scenarios: <scenarios, joined by ", ">`. Type: graph.ImpactItem[]

#### graph.Impact.reverify
The outer ring: units that use what changes and must be checked again. None is in the inner ring or changed. Type: graph.ImpactItem[]

#### graph.Impact.scopeGaps
For a ticket: features that write, emit or provide a contract in its scope while not in scope themselves, by ID. Type: graph.ScopeGap[]

#### graph.Impact.unresolved
For a ticket: IDs in its scope that name no unit, in natural ID order. Type: string[]

### graph.ImpactItem
Kind: type · Status: active
One unit in a ring.

#### graph.ImpactItem.id
A feature, contract, member, invariant or screen ID. Type: string

#### graph.ImpactItem.via
Why it is reached, one entry per path, sorted. Type: string[]

#### graph.ImpactItem.scenarios
The scenarios whose tests the change reaches through it, in natural ID order. Type: string[]

#### graph.ImpactItem.depth
Re-verify items only, and only with a depth above 1: how many steps from the change it was first reached. In text, ` [depth <n>]` after the title. Type: int?

### graph.ScopeGap
Kind: type · Status: active
A feature a ticket's scope should name but does not.

#### graph.ScopeGap.id
The feature. Type: string

#### graph.ScopeGap.text
`<feature> <link> <contract>, …: add it to touches`. Type: string

### graph.UnknownId
Kind: error · Status: active
The argument names no unit, term or ticket the command takes. Prints `Unknown <arg>.`, then ` Did you mean <closest>?` when a known ID is within the edit distance of a typo (at most 2, or a third of the argument's length when that is more), then a blank line and the usage text, on stderr, and exits 2.

#### graph.UnknownId.id
The argument as given. Type: string

#### graph.UnknownId.suggestion
The closest known ID, ignoring case, or null. Type: string | null

### graph.NotAnImpactTarget
Kind: error · Status: active
`spec impact` was given a module name. Prints `impact takes a feature, scenario, rule, contract, field, invariant, decision, screen or ticket, not module <name>`, a blank line and the usage text on stderr, and exits 2.

#### graph.NotAnImpactTarget.id
The module name as given. Type: string
