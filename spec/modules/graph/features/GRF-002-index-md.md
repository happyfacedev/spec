## Intent
`index.md` is the one generated file a team commits: a map of every module, by domain, with one line per feature, so a reader or an agent can find a feature without opening the folders. It holds nothing that changes with every edit, no spec version and no line numbers, so a pull request changes it only when it adds, renames or retires a module or a feature, and two branches rarely touch it.

## Behaviour
### S1: The fixture's index
Given the "chat-mini" fixture spec is the spec root, and its "config.json" has the name "chat"
When the developer runs "spec build" through graph.Build
Then graph.Index is exactly:
```markdown
# chat-spec index

Generated by `spec build`. Do not edit; run `spec show <ID>` for any line.

## ai

### providers · PRV
Runs the fake model providers.

- PRV-001 Stream a reply from the active provider
- PRV-002 Fall back when a provider rate-limits
- PRV-003 Track token usage per message

## chat

### conversation · CNV
Owns the messages of a conversation: sending a message to the active provider, stopping a reply mid-stream, and exporting a conversation to Markdown.

- CNV-001 Send a message
- CNV-002 Stop a reply mid-stream
- CNV-003 Export a conversation to Markdown

## workspace

### settings · SET
Owns the workspace settings that users change by hand: which providers are enabled and the API keys used to call them.

- SET-001 Enable providers
- SET-002 Manage API keys
```
And the file ends with a single newline

### S2: The title names the project
Given a spec whose "config.json" has the name "shop"
When the developer runs "spec build" through graph.Build
Then graph.Index.title is "# shop-spec index"

### S3: A spec with no project name
Given a spec whose "config.json" has no name, and whose spec root holds no "SKILL.md"
When the developer runs "spec build" through graph.Build
Then graph.Index.title is "# Spec index"

### S4: Domains sorted by name, modules by ID
Given a spec with module "zeta" in domain "billing", module "alpha" in domain "sales" and module "beta" in domain "billing"
When the developer runs "spec build" through graph.Build
Then graph.Index.domains are "## billing" holding "### beta" then "### zeta", then "## sales" holding "### alpha"

### S5: Only the first sentence of a module's description
Given module "providers" is described as "Runs the fake model providers. It streams a reply from the active provider, counts tokens, and finishes the reply on the workspace's fallback provider when the active one rate-limits."
When the developer runs "spec build" through graph.Build
Then graph.IndexModule.summary for "providers" is "Runs the fake model providers."

### S6: A module that is not active says so
Given module "settings" with prefix "SET" has status deprecated
When the developer runs "spec build" through graph.Build
Then graph.IndexModule.heading for it is "### settings · SET (deprecated)"

### S7: A feature that is not active says so, and what replaces it
Given feature "SET-002" titled "Manage API keys" is deprecated with superseded_by "SET-001"
And feature "SET-003" titled "Import keys" is removed with no superseded_by
When the developer runs "spec build" through graph.Build
Then graph.IndexModule.features holds "- SET-002 Manage API keys (deprecated → SET-001)" and "- SET-003 Import keys (removed)"

### S8: A module with no features
Given module "billing" has the description "Charges for orders." and no features
When the developer runs "spec build" through graph.Build
Then graph.Index holds the line "### billing · BIL", then "Charges for orders.", then a blank line, and no feature line for it

### S9: No spec version and no line numbers
Given the "chat-mini" fixture spec is the spec root
When the developer runs "spec build" through graph.Build
Then graph.Index holds no "spec@" and no line number (R1)

### S10: Edits that leave the map alone leave the file alone
Given the "chat-mini" fixture spec has just been built
And a glossary term has since been added, and a scenario's steps changed
When the developer runs "spec build" through graph.Build
Then graph.Index is byte-identical to before, and stdout does not hold "wrote index.md" (R1, INV-005)

### S11: A new feature title changes the file
Given the "chat-mini" fixture spec has just been built
And the title of "SET-002" has since changed to "Manage keys"
When the developer runs "spec build" through graph.Build
Then graph.Index holds "- SET-002 Manage keys", and stdout holds "wrote index.md" (R1)

## Rules
- R1: `index.md` changes only when a module's ID, prefix, domain, status or first sentence changes, or a feature's ID, title, status or superseded_by does, or a module or feature is added.

## Out of scope
- Resolving a conflict in `index.md` when merging: `spec merge` rebuilds it
- Checking that the committed file is fresh: `spec lint --ci`
