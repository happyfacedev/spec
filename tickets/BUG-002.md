From the S3 final review (U1). `changedPaths` (src/io/git.ts:164-176) reads `git status --porcelain` with rename detection on and skips the source path of a staged rename. It feeds the role scope checks (src/cli/report.ts:64) and the stash scope (src/io/stash.ts:25), so a staged `git mv` of a protected or out-of-scope file reports only the new path and the removal of the protected path is missed. Use `--no-renames` (git ≥ 2.18) or keep both paths of a rename entry; test that a `git mv` of a protected file is refused by the role scope check. Lesson for the neighbour checklist: 'anything that reads paths from git', not only diff readers.
